# Florida Wastewater Infrastructure & Flood Impact Dashboard

An interactive Leaflet dashboard for exploring Florida wastewater facilities and
recent FDEP Public Notice of Pollution (PNP) records. The dashboard displays
facility locations, source attributes, filters, charts, and preliminary
facility-to-incident matches.

## Requirements

- Python 3.10 or newer
- Internet access when downloading data and loading OpenStreetMap tiles

Install the Python dependencies:

```powershell
python -m pip install -r requirements.txt
```

## Getting started

From the project folder:

```powershell
python scripts/download_data.py
python scripts/make_plots.py
python -m http.server 8000
```

Open <http://localhost:8000> in a browser.

The dashboard must be served over HTTP. Opening `index.html` directly with a
`file://` URL can prevent the browser from reading the local GeoJSON files.

## Project files

- `index.html` — dashboard UI and client-side map, filtering, charts, and
  incident matching.
- `scripts/download_data.py` — downloads the FDEP WAFR facility layer and the
  current/recent PNP layer as both GeoJSON and CSV.
- `scripts/make_plots.py` — creates exploratory PNG charts from the facility
  CSV.
- `data/incident_template.csv` — optional normalized incident schema template.
- `data/` — downloaded facility and incident data used by the dashboard.
- `plots/` — generated exploratory charts.
- `requirements.txt` — Python dependencies.

Downloaded datasets and generated plots are ignored by Git. A fresh checkout
must run `download_data.py` before the dashboard can display map data.

## Local data used by the dashboard

At startup, `index.html` loads:

- `data/fl_wastewater_facilities.geojson` — FDEP WAFR wastewater facilities.
- `data/fdep_pnp_recent.geojson` — FDEP Public Notice of Pollution records.

The dashboard no longer loads the live facility ArcGIS service and does not
require an incident CSV upload. The local files are generated by
`download_data.py`.

## Incident matching

Facility-to-incident matching is preliminary. For each facility, the dashboard
checks the following in order:

1. A shared facility or permit identifier.
2. A normalized facility name, ignoring case, spaces, and punctuation.
3. Coordinates within 0.5 kilometers when identifiers or names do not match.

The popup reports the number of matching incidents and displays their facility
or incident names. A match is an indication for investigation, not proof that
the incident was caused by the facility or by flooding.

## Data limitations

The PNP endpoint used by the downloader is labelled as a recent/last-30-days
view and should not be treated as a complete historical incident archive.
Use a historical wastewater spill or SSO dataset for long-term analysis.

The WAFR layer is an inventory of facility locations and attributes. A mapped
facility does not imply that a spill occurred. Facility names, coordinates, and
identifiers can differ between FDEP and incident records, so approximate
matches require validation.

The dashboard does not infer flood causation. Flood exposure, reported cause,
and inferred cause should remain separate fields in any research dataset.

## Data sources

- [FDEP WAFR facility metadata](https://geodata.dep.state.fl.us/datasets/FDEP::wastewater-facility-regulation-wafr-wastewater-facilities/about)
- [FDEP WAFR ArcGIS layer](https://ags.dep.state.fl.us/arcgis/rest/services/OpenData/WAFR/MapServer/3)
- [FDEP Public Notice of Pollution information](https://floridadep.gov/water/industrial-wastewater/content/public-notice-pollution)
- [FEMA National Flood Hazard Layer](https://www.fema.gov/flood-maps/national-flood-hazard-layer)
- [NOAA CO-OPS](https://tidesandcurrents.noaa.gov/)

OpenStreetMap attribution is displayed in the map. Follow the
[OpenStreetMap tile usage policy](https://operations.osmfoundation.org/policies/tiles/)
when deploying or scaling the dashboard.
