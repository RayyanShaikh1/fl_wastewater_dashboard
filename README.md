# Florida Wastewater Infrastructure & Flood Impact Dashboard

An interactive Leaflet dashboard for exploring Florida wastewater facilities and
the last ten years of FDEP Public Notice of Pollution (PNP) records. The dashboard displays
facility locations, source attributes, filters, charts, and preliminary
facility-to-incident matches.

## Requirements

- Python 3.10 or newer
- Internet access when downloading data and loading OpenStreetMap tiles

Install the Python dependencies:

```powershell
python -m pip install -r requirements.txt
```

## Getting started

From the project folder:

```powershell
python scripts/download_data.py
python scripts/make_plots.py
python scripts\server.py
```

Open <http://localhost:8000> in a browser. Use `server.py`, not
`python -m http.server`, because the dashboard uses its SQLite incident API.
Keep the server terminal open while using the dashboard. A `KeyboardInterrupt`
message means the server was stopped with Ctrl+C; it is not a data-loading
error. If port 8000 is already in use, run:

```powershell
$env:DASHBOARD_PORT="8001"
python scripts\server.py
```

Then open <http://localhost:8001>.

The dashboard must be served over HTTP. Opening `index.html` directly with a
`file://` URL can prevent the browser from reading the local GeoJSON files.

## Project files

- `index.html` — dashboard UI and client-side map, filtering, charts, and
  incident matching. It loads facilities first and requests selected incidents
  from the API.
- `scripts/server.py` — local standard-library HTTP server and SQLite API.
  It builds `data/incidents.sqlite3` from the downloaded PNP archive on first
  start or after the source archive changes. `/api/summary` returns compact
  all-years counts; `/api/incidents` returns only the selected period and
  only fields needed by the dashboard.
- `scripts/download_data.py` — downloads the FDEP WAFR facility layer and the
  PNP "All" layer filtered server-side to the last ten years as both GeoJSON
  and CSV, and creates one incident GeoJSON/CSV pair per year plus
  `data/pnp_years.json`. Set `PNP_YEARS` before running to use a different
  number of years.
- `scripts/make_plots.py` — creates exploratory PNG charts from the facility
  CSV.
- `data/incident_template.csv` — optional normalized incident schema template.
- `data/` — downloaded facility and incident data used by the dashboard.
- `plots/` — generated exploratory charts.
- `requirements.txt` — Python dependencies.

Downloaded datasets and generated plots are ignored by Git. A fresh checkout
must run `download_data.py` before the dashboard can display map data.

## Local data used by the dashboard

At startup, `index.html` loads:

- `data/fl_wastewater_facilities.geojson` — FDEP WAFR wastewater facilities.
- `data/incidents.sqlite3` — indexed local incident database used by the API.
- `data/fdep_pnp_YYYY.geojson` — optional yearly exports for inspection.

The dashboard no longer loads the live facility ArcGIS service and does not
require an incident CSV upload. The local files are generated by
`download_data.py`.

## Incident matching

Facility-to-incident matching is preliminary. For each facility, the dashboard
checks the following in order:

1. A shared facility or permit identifier.
2. A normalized facility name, ignoring case, spaces, and punctuation.
3. Coordinates within 0.5 kilometers when identifiers or names do not match.

The popup reports the number of matching incidents and displays their facility
or incident names. A match is an indication for investigation, not proof that
the incident was caused by the facility or by flooding.

## Data limitations

The downloader uses FDEP's PNP "All" layer with a server-side
`DATE_TIME_OF_REPORT` filter. It retrieves the last ten years at download time;
rerun the downloader periodically to keep the local snapshot current. PNP
records are public notices and should not be treated as a complete wastewater
spill or SSO archive.

The browser never loads the ten-year archive directly. SQLite filters by year
on the server using an indexed `year` column. This is intentionally a small
Python API rather than Angular: Angular would add a build pipeline and would
not improve the expensive data access operation, which belongs on the backend.

## Dashboard charts and analysis

- **Facilities by status/type** describe the current WAFR inventory, not
  historical incidents.
- **Incidents by year** is preloaded from SQLite and always shows all
  available years. It is independent of the selected year/range filter.
- **County incident groups** ranks counties by notice count. Clicking a county
  filters the facility map and reports facility count, incident count, incident
  rate per facility, and facility types.
- **County clusters** is an exploratory three-group k-means analysis using
  incident count, facility count, and incidents per facility. The labels mean
  **High incident count**, **Many facilities**, or **High incident rate** based
  on the dominant average feature in each group. It is not a causal model or
  prediction model. County names in affected-county text are
  normalized approximately, and a notice does not establish flooding,
  duration, magnitude, or facility impact.

The current data does not reliably provide flood duration, flood magnitude,
capacity impact, or a complete facility-impact outcome. Those fields should be
added and validated before fitting the planned binomial/logistic prediction
model.

### Quick-reference keys

- Facility status: `A` active, `X` inactive, `T` temporary, `U` unknown, and
  `C` closed. These are source values from FDEP.
- Facility type: `DW` domestic wastewater, `IW` industrial wastewater, `CBP`
  combined/centralized basin, `AFO` animal feeding operation, `RAF`
  reclaimed-water facility, `UIC` underground injection control, `RES` reuse,
  `PET` petroleum-related, `CFO` concentrated feeding operation, `ISW`
  industrial solid waste, and `REU` reuse-related. Source classifications can
  overlap and should be confirmed against FDEP metadata.

The WAFR layer is an inventory of facility locations and attributes. A mapped
facility does not imply that a spill occurred. Facility names, coordinates, and
identifiers can differ between FDEP and incident records, so approximate
matches require validation.

The dashboard does not infer flood causation. Flood exposure, reported cause,
and inferred cause should remain separate fields in any research dataset.

## Data sources

- [FDEP WAFR facility metadata](https://geodata.dep.state.fl.us/datasets/FDEP::wastewater-facility-regulation-wafr-wastewater-facilities/about)
- [FDEP WAFR ArcGIS layer](https://ags.dep.state.fl.us/arcgis/rest/services/OpenData/WAFR/MapServer/3)
- [FDEP Public Notice of Pollution information](https://floridadep.gov/water/industrial-wastewater/content/public-notice-pollution)
- [FEMA National Flood Hazard Layer](https://www.fema.gov/flood-maps/national-flood-hazard-layer)
- [NOAA CO-OPS](https://tidesandcurrents.noaa.gov/)

OpenStreetMap attribution is displayed in the map. Follow the
[OpenStreetMap tile usage policy](https://operations.osmfoundation.org/policies/tiles/)
when deploying or scaling the dashboard.
